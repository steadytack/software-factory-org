# The software factory in one page

**A quick, safe way to turn staff ideas into working apps, built with AI and decided by people.**

```
Idea card ─→ Assess (days) ─→ Gate 1: decide ─→ Spike (about a week) ─→ grow │ keep │ stop
                                            └─→ Spec ─→ Build and audit ─→ Publish   (for ideas ready to specify)
```

## Why
- **Faster:** most ideas start as a spike, a working version in about a week, instead of a project.
- **Cheaper to be wrong:** a spike that fails costs a week, and the factory records what it learned.
- **Reuse:** apps are built from the organisation's approved building blocks and templates where they fit.
- **Evidence:** every idea is assessed before money is spent, and every published app is reviewed after 30 and 90 days against its success measures.

## How it stays safe
1. People decide at four gates; AI does the work between them.
2. Nothing leaves the organisation or goes live without a typed approval.
3. Only the data classes the organisation allows are used, and personal or confidential data needs approval or test data.
4. Each app is protected for the data it holds and who can reach it, whatever its size.
5. Every app is audited against its spec before release, and results are reported exactly as run.

## Four sizes, each a decision
**Spike** (a quick try) → **Exploration prototype** (to react to) → **Business prototype** (does real work) → **Production app** (relied on and supported). Moving up a size is always a decision, never drift, so the factory does not create unsupported shadow IT.

## How we're doing
`python factory/scripts/status.py` prints the cycle times so far: the median days from idea to decision, and from decision to a finished build, and how many spikes ended within their time box.
